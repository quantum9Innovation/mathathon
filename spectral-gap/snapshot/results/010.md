# 010: batch runner smoke test

**Status: done.** Verified `.orchestrator/bin/batch.py` end to end.

## What was checked

| path | result |
| --- | --- |
| `start` | writes `state.json`, prints deadline, flips frontmatter to `running` |
| `check --json` | returns `remaining_ms`, plus `0` and `over: true` once past the deadline |
| `extend N "why"` | pushes the deadline and records the reason in `state.json` |
| `close` | appends to `LEDGER.md` and `logs/<id>.log`, clears `state.json` |
| `start` twice | refused while another batch is open |
| `start` without `budget_s` | refused |
| `check` when idle | exit 4 |
| over budget | `check` exits 3, `next`/`close` unaffected |

## What is not enforced

The budget bounds *my* work at command granularity, not the machine's. A
`shell_exec` command with a `timeout_ms` inside the budget is bounded by the OS.
a background job launched during a batch keeps running after it closes. A batch
that ends by launching a job should record the job id in `results/<id>.md` and
do the check in a later batch.
